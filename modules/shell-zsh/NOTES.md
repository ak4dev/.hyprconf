## Deliberately not carried

- **`meta='%244F'`** from the wizard dump (grey for an up-to-date git segment's `#tag`/`@commit`/`:remote` text; the template uses 248). It lives inside the template's own `my_git_formatter`, and rewriting the live function through `functions[my_git_formatter]` **corrupts every multibyte glyph in the body** — zsh 5.9.2 re-metafies it, U+21E3 comes back as U+20E7 plus a stray byte (reproduced; the git segment's ⇣⇡⇠⇢ would break). Written in the file header.
- **`POWERLEVEL9K_MULTILINE_FIRST_PROMPT_GAP_FOREGROUND=238`**: the template only sets it inside `if [[ $GAP_CHAR != ' ' ]]`, which never fires with the classic `GAP_CHAR=' '`. Carrying it unconditionally was the one place the transcription would have differed from today's live prompt.
- **`per_directory_history`** in the right prompt: an Oh My Zsh plugin indicator, inert once OMZ is gone (install-core.5#2 says to drop it).

## Cross-module facts

- `~/.config/kitty/kitty.conf` now carries **two** hyprconf includes — `hyprconf.conf` (terminal-kitty) and `hyprconf-zsh.conf` (this module). AGENTS rule 6's "beyond the one `include`" wording needs to become "one include per module". The two modules are order-free, but only because **both** seed an absent `kitty.conf` from `$OMARCHY_PATH/config/kitty/kitty.conf` before appending (the theme include lives only in that stub, `config/kitty/kitty.conf:1-2`; `omarchy-install-terminal:39-42` is the shape). Whichever runs first seeds it; the other's `grep -qxF` then guards its own line. Keep both seeds: with one of them dropped, that module creates a `kitty.conf` holding nothing but its include and kitty loses Omarchy theming for good. This module appends ONE bare `include hyprconf-zsh.conf` (no `# hyprconf overlay` comment line, which terminal-kitty's undo `sed` deletes globally) with no blank separator, so each undo is byte-exact — verified both orders in a throwaway HOME, ending at Omarchy's stub byte for byte.
- terminal-kitty must NOT write a `shell` line any more; if its `hyprconf.conf` is reinstalled each run, an appended `shell` line there would be lost — that is why this one lives in its own file.
- `fastfetch` ships `~/.config/hyprconf/fastfetch.jsonc` (brief decision 11); the greeting reads it when present.
- The core must install `~/.local/bin/hyprconf` before `hyprsync` works.
- One file in the state dir: `${HYPRCONF_STATE:-~/.local/state/hyprconf}/p10k-cloned`, empty, written only by the clone itself. It is provenance, not a latched user choice (nothing else is gated on it): `undo` deletes `~/.local/share/powerlevel10k` only when the marker says this module made it, so a checkout of the user's that the install merely adopted and moved to the pin survives. `undo` then `rmdir`s the state and `~/.local` directories it may have created — `rmdir` refuses a non-empty one, so a sibling's marker keeps the shared directory alive (verified beside terminal-kitty's `terminal-applied`). It also removes a `~/.zshrc` it created once the source line is out and nothing else is in it (stock Omarchy has no `~/.zshrc`; `/etc/skel` is bash-only), never a symlink and never a file with content.
