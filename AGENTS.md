# Agent instructions

The one directive file for this repo. `CLAUDE.md` is a symlink to it — Claude Code reads `CLAUDE.md`, not `AGENTS.md`, so this file loads into every session and is re-injected after `/compact`; keep the symlink, and keep this file short (its length is context, every session). `README.md` is the user contract and keeps 1:1 parity with the code; `docs/CONTRIBUTING.md` holds the tree, the test tree and seam lists, the publish flow and the website upload. One home per fact — link, never restate.

## What hyprconf is

- A lean overlay on a stock [Omarchy](https://omarchy.org): `install.sh` plus the payload it ships, nothing else. Omarchy owns packages, session, shell, theme engine, idle/lock and bar; hyprconf layers one person's preferences on top through Omarchy's own seams (map below) and disturbs the install as little as possible. `install.sh` is the only entry point — run with no payload beside it (the curl path) it clones `stable` and hands over; nothing is packaged, the promoted branch is the release.
- Verified against Omarchy 4.0.3-1 (Hyprland 0.56.2, quickshell 0.3.1 — Arch's package, renamed off `-git`; uwsm 0.26.7, Bash 5.3). This line is the pin: a version named inside a code comment or a test is that fact's own provenance and stays as written.
- Posture: a personal config shared as-is — not a product, no support obligation. No `LICENSE`, deliberately: default copyright applies and that is the intent — do not add one. Favour deleting over adding: every line ships into a user's `$HOME`.
- Gone for good, never rebuilt: the TUI, the standalone dotfiles/ISO suite, the 68-theme engine, the release tarball, and any deploy tooling or web app. `web/` is one static `index.html` (+ `favicon.svg`): no build, no JS, no external requests.

## Hard rules

1. **Omarchy's own tools first.** Before any custom mechanism, check `omarchy commands --json`, `/usr/share/omarchy/bin/` and the seams in the map; a hand-rolled replacement for something Omarchy does is a drift bug. A custom path is allowed only where Omarchy has no tool, and the comment beside it says what was checked.
2. **Never work from memory about Omarchy.** `/usr/share/omarchy/` is authoritative for the installed version (`omarchy version`); read it, never edit it. Diff `default/hypr/*.lua` before adding a Hyprland value; read `bin/` for what a command really does (several check less than they appear to); read `shell/` for the plugin contract. Use `grep -R` there — every file in `/usr/share/omarchy/bin` is a symlink into `/usr/bin`, which `grep -r` skips. Cite the file or command that justifies each claim about Omarchy, and name the Omarchy version in the commit message. Where the overlay needs a list of Omarchy's commands, plugins or themes, derive it at runtime.
3. **Packages: official Arch repos, through `omarchy-pkg-add`** (one `packages` file per module, beside its `install`; `install.sh` installs nothing of its own), plus Omarchy's own `[omarchy]` repo only when an Omarchy installer owns the package (`omarchy-install-editor-vscode` → `visual-studio-code-bin`; Firefox via `omarchy-install-browser firefox`). Never `pacman`, `yay`, `paru`, `makepkg` or any of Omarchy's AUR wrappers (`omarchy-pkg-aur-*`, `omarchy-update-aur-pkgs`) on any path, and no removals: `omarchy-pkg-drop` is never called (a conflicting package the user installed — Arch's Code - OSS beside Omarchy's VS Code — is theirs to drop; `modules/vscode` warns). An AUR-only need is raised with the user, not implemented. Confirm with `pacman -Si <pkg>` (`Repository: core|extra|omarchy`). Nothing already in Omarchy's base is listed; an orphan package goes with the hotkey that wanted it.
4. **No PII in tracked files** — names, emails, hostnames, IPs, MACs, serials, keys, AWS ids, `/home/<user>` paths — configs, docs, scripts and commit messages alike. Use `~`, `$HOME`, `$USER`, `testuser`. `tests/test_no_pii.py` derives the identities at runtime and scans every file in the checkout (an on-disk walk, not `git ls-files`). The `Co-Authored-By: … <noreply@anthropic.com>` / `Claude-Session:` commit trailers are allowed — a noreply address is not PII.
5. **Idempotent, reversible, set-once.** Every module re-runs byte-stably — the post-update hook runs `hyprconf --no-update --no-packages` (through the `~/.local/bin` link) after every `omarchy-update`; a user choice (font, default apps, idle, clock, widget enables) is applied once behind a marker in `~/.local/state/hyprconf/` and never re-asserted; every module has a stock-restoring `install undo`, and `hyprconf --undo` runs them all in reverse (README › Reverting to stock). Nothing lands in `$HOME` by hand: every file ships in the repo and is wired through a module.
6. **Restraint.** Never `chsh` (the login shell stays bash — the reason, once, in [`modules/shell-zsh`](modules/shell-zsh/README.md)); `install.sh` writes outside `$HOME` never, and a module only through its own gates (rule 3's package commands, `modules/firefox`'s system policy, `modules/keychron`'s udev rule) — the one user-run tool that goes further, `modules/yubikey`'s `hyprconf-yubikey` (its two drop-ins, `limine-mkinitcpio`, a LUKS slot), says so in [its README](modules/yubikey/README.md); `sudo` only in a module that declares it, all behind `--no-packages` (the hook passes it, and it exports `HYPRCONF_NO_SUDO` for the modules); Firefox, VS Code and every module bow out without a terminal (a module with packages says so in one line and exits 0; a *failed* `omarchy-pkg-add` still fails that module); never rewrite Omarchy's `kitty.conf` beyond one `include` per module; never switch the active theme; never touch `monitors.lua`; never overwrite a seeded preset; never point `omarchy-default-terminal` at an absent terminal. `tests/test_core.py`, `tests/test_scans.py` and each module's own `test_<name>.py` assert these.
7. **Code, tests and docs move together, in one commit.** A changed stage, flag, script, path, package, hotkey, preset or plugin updates its tests and `README.md` (grep it for what you touched; nothing may describe what no longer exists). Never weaken a test for a green run: an intended behaviour change updates the test to the new contract and says so in the commit. Never alter the README branding block (banner + badges).
8. **Security is a gated invariant, not a review note.** The trust model, one line each: nothing an unprivileged process can write may steer a root action; untrusted content (window titles, feeder output, network bytes) is data, never code; what ships to strangers is clone-only over https and pinned — CI actions by sha, third-party shell repos by commit, and bumping a pin is a deliberate release. The mechanical floor: the fetch-and-execute and secret scans, the root-write `--` shape, the bootstrap/https, CI least-privilege and settings-guardrail pins (`tests/test_supply_chain.py` and `tests/test_scans.py`). A change that adds a network touch, a root write, a broader udev match or a new `eval` updates the matching pin in the same commit — the why written beside it — or does not land. Full model and checklist: CONTRIBUTING › Security.

## Deliberate non-Omarchy choices — keep them, and the reason

| Choice | Why |
|---|---|
| `modules/hypr/*.lua` **copied** into `~/.config/hypr/` (cmp-gated `install -m 644`), not symlinked; `hyprconf hypr` (`bash ~/.hyprconf/install.sh hypr`) after an edit | an `omarchy refresh` or a migration then lands on the copy and the next run puts it back — no clobber guard, no stock-template cache, and the checkout stays `git status` clean; the price is one command after an edit |
| `hyprconf.clock` shipped as `modules/bar-clock/plugin` and **symlinked** into `~/.config/omarchy/plugins/`, not made by `omarchy plugin clone` (nor copied at install time) | clone hardcodes `<username>.<id>` — a username in shipped config is PII — and a copy made once on the box was frozen at the release that made it (4.0.2's hardening of its own `Panel.qml` never reached it); the link makes a `git pull` the update, carries Omarchy's MIT `NOTICE`, loads the panel from the running Omarchy, and the module's parity test turns red on an Omarchy release that changes the clock |

## The Hyprland copies

`modules/hypr/{bindings,input,looknfeel}.lua` become `~/.config/hypr/*.lua` by copy, so an edit is live only after `hyprconf hypr`. Every save must parse (`luac -p modules/hypr/*.lua`), state only deltas from `/usr/share/omarchy/default/hypr/`, and any command a new bind runs must already be on PATH — `command -v` it before you commit; `modules/hypr/test_hypr.py` covers only the `hyprconf-*` half, and Hyprland runs a missing target as a silent no-op. `mainMod` is `SUPER`; every key Omarchy also binds goes through `rebind()`, which unbinds the keysym and the keycode form (digits and `-`/`=`) before `o.bind`; never restate a bind Omarchy already has (`SUPER+P`, arrows, scroll, mouse drag — `test_hypr.py`); a hotkey that launches a program outside Omarchy's base adds it to the `packages` file of the module that owns it. A new preset is one more `*Monitors*.lua` file in the module — the seed and the tool's `-h` line derive from the glob — plus a row in the module README and a case in `test_hypr.py`. A desk preset names its displays `output = "desc:<make> <model>"` — never a connector, which renumbers when a cable moves between GPUs — carries no serial (PII), and ends with the `output = ""` catch-all; `test_hypr.py` pins all three.

## Scripts

- `#!/usr/bin/env bash` and `set -euo pipefail`; a script that deviates (the hooks and `hyprconf-yubikey` drop `-e`, `hyprconf-stats` is `set -u`) says why in a comment.
- Runtime Hyprland changes go through `hyprctl eval` and `hyprctl dispatch 'hl.dsp.…'` (quirks). A hotkey-launched script with something to say says it through `omarchy-osd` / `omarchy-notification-send` (`hyprconf-monitor-preset`); `hyprconf-gaps` says nothing — the gap change is its feedback, and its one failure (`hyprctl eval` refusing) is stderr + exit 1, invisible from the hotkey and accepted. No `pkill` / `killall`.
- Anything outside `$HOME` a script reads or writes sits behind a `: "${_HYPRCONF_X:=/default}"` seam — the Omarchy tree through Omarchy's own `OMARCHY_PATH` (`default/bash/env-bootstrap`), the feeders through `HYPRCONF_STATS_*` / `HYPRCONF_GPU_*` — never `readonly` (lists: CONTRIBUTING › Writing hermetic tests).

## Branches, publish, deploy

- `dev` is the working branch; `stable` is what users clone and what `hyprconf.sh` serves. Only `scripts/publish` writes `stable` (the three gates → tag `v$(<VERSION)` → one atomic push of `dev`, `stable` and the tag), and only when the user says "publish", with CI green on `dev`. Never push to `stable` by hand; never push anywhere unless the user asks; commit when asked.
- Nothing in the repo deploys. The website upload is by hand, only when the user says "deploy", after a publish, and always `stable`'s `install.sh`: CONTRIBUTING › Updating the website.

## Commits and versions

- [Conventional Commits](https://www.conventionalcommits.org/): `<tag>(<scope>): <message>`, subject ≤ 140 characters; tags `feat fix docs style refactor perf test build ci chore revert`; `!` or a `BREAKING CHANGE:` footer for removed or renamed hotkeys, stages, flags, plugin ids or paths. Name the Omarchy version the change was verified against.
- [SemVer](https://semver.org/) in the top-level `VERSION` file, bumped by hand in the commit that earns it — minor for a `feat`, major for a breaking change. `scripts/publish` reads it and takes no options; it refuses a tag that already exists on another commit.

## Tests

- Hermetic suites, all collected in one run (`testpaths = ["modules", "tests"]`): `modules/<name>/test_<name>.py` beside each module's `install`, plus `tests/` — the core, the tree-wide scans, the plugin contract, PII, the supply chain and the publish pipeline — and that is the whole suite; behaviour that needs a live session is verified by hand and recorded in the commit message. Tree and seam lists: CONTRIBUTING › Testing.
- Hermetic: both pass in a bare `archlinux:latest` container as an unprivileged user — no Hyprland or shell, no hardware, no real `$HOME`, no ambient state (identity, groups, a TTY are injected — `_HYPRCONF_ASSUME_TTY`), never mutating the container. `$HOME` is relocated wholesale; everything outside it is behind `OMARCHY_PATH` or a `_HYPRCONF_*` / `HYPRCONF_STATS_*` / `HYPRCONF_GPU_*` seam.
- Every command that could touch the desktop or the system is a fake bin first on PATH — `/usr/bin` carries every `omarchy-*` command, so every one a code path can call is stubbed. Pure tools (`jq`, `luac`, `qmllint`, `shellcheck`, `sh`, coreutils — the list: CONTRIBUTING › Writing hermetic tests) are real when present and the test skips otherwise; `git` is required (throwaway trees under `tmp_path` only); `omarchy-plugin-validate` is the one real `omarchy-*` command a test runs.
- Harness: the repo-root `conftest.py` hands every test the `box` fixture — a throwaway machine (tmp `$HOME`, `/etc` and `$OMARCHY_PATH`, and a fakes dir first on PATH holding a recording stub for every `omarchy-*` name the tree carries, derived from it) with `box.stub()`, `box.run()` / `box.core()` / `box.undo()`, `box.calls` / `commands` / `calls_of()` and `box.reset()`. A new test uses it; `tests/test_core.py` runs the core on it, and its `live` fixture adds the few bodied fakes a whole run needs (a shell that answers, a sourceable `omarchy-shell-config`, a git that settles the pin).
- CI has **no git identity** — the container has no `~/.gitconfig`, and a bare `git commit` there dies "unable to auto-detect email address": the root `conftest.py` exports `GIT_AUTHOR_*` / `GIT_COMMITTER_*` for the session, and every git a test runs inherits them.

## Gates and CI

Before every commit: `make check` — `make lint` (ruff check + format), `make shellcheck` (find-based; fails when it finds nothing) and `make test` (`pytest -n auto -rs`), the three gates `scripts/publish` runs; `make` alone runs only the suites. `.github/workflows/test.yml` runs the same `make check` on every push to any branch, in `archlinux:latest`, as an unprivileged `ci` user the job creates and gives the checkout to — root would bypass DAC, trip `install.sh`'s refuse-root preflight and make git call the workspace dubious. Exactly seven tests skip there, every one for the same reason — it needs the installed Omarchy: the four plugin modules' `omarchy-plugin-validate` runs, `modules/bar-clock`'s two stock-clock parity tests, and `modules/firefox`'s merge against Omarchy's own `default/firefox/policies.json`. Any other skip is a regression, and `-rs` names every skip in the log. CI must be green before a publish, and CI on the push is the container gate — the pre-push check is `make check`. Read a red run from its `::error::` **annotation** — the one part of a red run the public API hands back; the why is in the comment beside the tee step in `.github/workflows/test.yml`, and that step stays when the workflow is edited. Reproduce a container-only failure — the no-Omarchy `/usr/bin` where an unstubbed `omarchy-*` call fails loudly, the bare freshly-upgraded toolchain — with:

```bash
docker run --rm -v "$PWD":/src:ro archlinux:latest bash -c \
  'pacman -Syu --noconfirm --needed git make ruff python python-pytest python-pytest-xdist jq shellcheck diffutils lua qt6-declarative zsh &&
   cp -r /src /repo && useradd -m ci && chown -R ci: /repo && cd /repo && su ci -s /bin/bash -c "make check"'
```

## Known quirks (Omarchy 4.0.3-1, Hyprland 0.56.2, Firefox 155.0.1-1, Bash 5.3 — re-verify on upgrade)

- `hyprctl keyword` is a no-op — prints "keyword can't work with non-legacy parsers. Use eval." and exits 0 — and `dispatch dpms on` errors under the Lua parser: use `hyprctl eval` (exit 7 on error) and `hyprctl dispatch 'hl.dsp.…({ … })'` (forms in `modules/hypr/README.md`).
- Omarchy binds digits and `-`/`=` by keycode (`SUPER + SHIFT + code:20`, `default/hypr/bindings/tiling.lua`), which `hl.unbind` of the keysym does not match — both fire; the keycode unbind inside `rebind()` in `modules/hypr/bindings.lua` is load-bearing.
- `omarchy-update` re-execs under `script(1)` with `OMARCHY_UPDATE_LOGGED=1`, so every hook child has a pty and `[[ -t 1 ]]` is true there: anything the overlay prints or asks on that path gates on that variable, never on the tty test. Nothing does today — the overlay asks nothing at install time.
- A prompt runs only on a TTY: every one has a non-interactive path (`--yes`, or a refusal that says so) and `_HYPRCONF_ASSUME_TTY` for the suite. `hyprconf-yubikey` is the only tool that asks.
- Bar widgets never size off `parent`: the ModuleSlot takes its height from the widget's implicit size, so `parent.height` is a binding loop QML drops — bind `implicitWidth` / `implicitHeight` to content.
- `omarchy plugin clone` hardcodes `${USER}.<id>`; the registry swaps a `clonedFrom` copy into the stock slot at enable time only, and `shell.json`'s `bar.centerAnchor` does no clone resolution — `modules/bar-clock` moves it after the swap, and on every run, since an anchor can go stale long after the install (a removed clone leaves one naming nothing); its guard, not the clock marker, is what keeps a user's own anchor safe.
- A plugin folder installed as a SYMLINK is scanned (the third-party walk is a glob that follows one, `shell/services/PluginRegistry.qml:712-713`) but never watched: the shell's `inotifywait -r` does not descend a link (`:663-674`), so an explicit `omarchy-shell shell rescanPlugins` on every run is what picks a `git pull` up.
- A long-lived shell can refuse a *newly added* `entryPoints.service` with Qt's `File name case mismatch` (`WARN qml: service plugin load failed for <id>`) while the widget draws its null-service defaults. Nothing on disk is wrong — it is shell-lifetime state, not a plugin defect: `omarchy restart shell` clears it, so restart before changing the plugin.
- Firefox: the `Preferences` policy's silent allowlist drop (a `startsWith` prefix match, and the `"Type"` rule every int-valued pref carries), the `browser.uiCustomization.state` seeding rules, the built-in themes' `inApp` quirk that leaves `:root[lwtheme]` off and `SearchEngines` applying on release are pinned — with their sources, the version each was verified on and the recipe to re-derive them — in `modules/firefox/test_firefox.py` and `modules/firefox-theme/{hook,test_firefox_theme.py}`. Read those before touching either module's payload.
- Bash 5.3: `$(< file 2>/dev/null)` returns empty — use `read -r var < file` or `$(cat file 2>/dev/null)`.
- Never `git update-index --skip-worktree` — it hides tracked files from the working tree.
- Branding: `.hyprconf` (leading dot), except the domain `hyprconf.sh`, binaries `hyprconf-*` and plugin ids `hyprconf.*`.

## How to work here

1. Read this file; read the README section and the code comments for what you touch — they carry the reasoning.
2. Verify every Omarchy fact on the box before changing anything (rule 2).
3. Change code, tests and docs together; keep `README.md`, `docs/CONTRIBUTING.md` and this file in lockstep, one home per fact.
4. `modules/hypr/*.lua`: every save luac-clean, deltas only, targets on PATH — then `hyprconf hypr` to make it live.
