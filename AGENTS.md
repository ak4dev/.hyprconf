# Agent instructions

The one directive file for this repo. `CLAUDE.md` is a symlink to it — Claude Code reads `CLAUDE.md`, not `AGENTS.md`, so this file loads into every session and is re-injected after `/compact`; keep the symlink, and keep this file short (its length is context, every session). `README.md` is the user contract and keeps 1:1 parity with the code; `docs/CONTRIBUTING.md` holds the tree, the test tree and seam lists, the publish flow and the website upload. One home per fact — link, never restate.

## What hyprconf is

- A lean overlay on a stock [Omarchy](https://omarchy.org): `install.sh` plus the payload it ships, nothing else. Omarchy owns packages, session, shell, theme engine, idle/lock and bar; hyprconf layers one person's preferences on top through Omarchy's own seams (map below) and disturbs the install as little as possible. `install.sh` is the only entry point — run with no payload beside it (the curl path) it clones `stable` and hands over; nothing is packaged, the promoted branch is the release.
- Verified against Omarchy 4.0.3-1 (Hyprland 0.56.2, quickshell 0.3.1 — Arch's package, renamed off `-git`; uwsm 0.26.7, Bash 5.3). This line is the pin: a version named inside a code comment or a test is that fact's own provenance and stays as written.
- Posture: a personal config shared as-is — not a product, no support obligation. No `LICENSE`, deliberately: default copyright applies and that is the intent — do not add one. Favour deleting over adding: every line ships into a user's `$HOME`.
- Gone for good, never rebuilt: the TUI, the standalone dotfiles/ISO suite, the 68-theme engine, the release tarball, and any deploy tooling or web app. `web/` is one static `index.html` (+ `favicon.svg`): no build, no JS, no external requests.

## Hard rules

1. **Omarchy's own tools first.** Before any custom mechanism, check `omarchy commands --json`, `/usr/share/omarchy/bin/` and the seams in the map; a hand-rolled replacement for something Omarchy does is a drift bug. A custom path is allowed only where Omarchy has no tool, and the comment beside it says what was checked.
2. **Never work from memory about Omarchy.** `/usr/share/omarchy/` is authoritative for the installed version (`omarchy version`); read it, never edit it. Diff `default/hypr/*.lua` before adding a Hyprland value; read `bin/` for what a command really does (several check less than they appear to); read `shell/` for the plugin contract. Use `grep -R` there — every file in `/usr/share/omarchy/bin` is a symlink into `/usr/bin`, which `grep -r` skips. Cite the file or command that justifies each claim about Omarchy, and name the Omarchy version in the commit message. Where the overlay needs a list of Omarchy's commands, plugins or themes, derive it at runtime.
3. **Packages: official Arch repos, through `omarchy-pkg-add`** (the `packages` file, or a stage), plus Omarchy's own `[omarchy]` repo only when an Omarchy installer owns the package (`omarchy-install-editor-vscode` → `visual-studio-code-bin`; Firefox via `omarchy-install-browser firefox`). Never `pacman`, `yay`, `paru`, `makepkg` or any of Omarchy's AUR wrappers (`omarchy-pkg-aur-*`, `omarchy-update-aur-pkgs`) on any path, and no removals: `omarchy-pkg-drop` is never called (a conflicting package the user installed — Arch's Code - OSS beside Omarchy's VS Code — is theirs to drop; the stage warns). An AUR-only need is raised with the user, not implemented. Confirm with `pacman -Si <pkg>` (`Repository: core|extra|omarchy`). Nothing already in Omarchy's base is listed; an orphan package goes with the hotkey that wanted it.
4. **No PII in tracked files** — names, emails, hostnames, IPs, MACs, serials, keys, AWS ids, `/home/<user>` paths — configs, docs, scripts and commit messages alike. Use `~`, `$HOME`, `$USER`, `testuser`, `@HYPRCONF_DIR@`. `tests/unit/test_no_pii.py` derives the identities at runtime and scans every file in the checkout (an on-disk walk, not `git ls-files`). The `Co-Authored-By: … <noreply@anthropic.com>` / `Claude-Session:` commit trailers are allowed — a noreply address is not PII.
5. **Idempotent, reversible, set-once.** Every stage re-runs byte-stably — the post-update hook runs `install.sh --no-update --no-packages` after every `omarchy-update`; a user choice (font, default apps, idle, clock, widget enables) is applied once behind a marker in `~/.local/state/hyprconf/` and never re-asserted; every stage has a stock-restoring undo (README › Reverting to stock). Nothing lands in `$HOME` by hand: every file ships in the repo and is wired through a stage.
6. **Restraint.** Never `chsh`; `install.sh` writes outside `$HOME` only through rule 3's package commands, the Firefox policy and the Keychron udev rule — the one user-run tool that goes further, `hyprconf-yubikey` (its two drop-ins, `limine-mkinitcpio`, a LUKS slot), says so in README; `sudo` only in the `packages`/`firefox`/`editor`/`keychron` stages, all behind `--no-packages` (the hook passes it); Firefox, VS Code and the Keychron rule bow out without a terminal, the packages stage does not — a missing package then fails on `sudo` and the run dies there; never rewrite Omarchy's `kitty.conf` beyond the one `include`; never switch the active theme; never touch `monitors.lua`; never overwrite a seeded preset; never point `omarchy-default-terminal` at an absent terminal. `tests/unit/test_omarchy_install.py` asserts these.
7. **Code, tests and docs move together, in one commit.** A changed stage, flag, script, path, package, hotkey, preset or plugin updates its tests and `README.md` (grep it for what you touched; nothing may describe what no longer exists). Never weaken a test for a green run: an intended behaviour change updates the test to the new contract and says so in the commit. Never alter the README branding block (banner + badges).
8. **Security is a gated invariant, not a review note.** The trust model, one line each: nothing an unprivileged process can write may steer a root action; untrusted content (window titles, feeder output, network bytes) is data, never code; what ships to strangers is clone-only over https and pinned — CI actions by sha, third-party shell repos by commit, and bumping a pin is a deliberate release. The mechanical floor: the fetch-and-execute and secret scans, the root-write `--` shape, the bootstrap/https, CI least-privilege and settings-guardrail pins (`tests/unit/test_supply_chain.py` and the scans beside the restraint tests). A change that adds a network touch, a root write, a broader udev match or a new `eval` updates the matching pin in the same commit — the why written beside it — or does not land. Full model and checklist: CONTRIBUTING › Security.

## Deliberate non-Omarchy choices — keep them, and the reason

| Choice | Why |
|---|---|
| `hypr/*.lua` symlinked into `~/.config/hypr/`, not copied | the checkout is the live config, edited in place; `omarchy refresh` writes through the links, so `restore_clobbered_override` puts the stock template back from git |
| `themes/dracula` symlinked into `~/.config/omarchy/themes/`, not copied | `git pull` in the checkout is the theme update; `omarchy-theme-set` takes the plain `cp -r` branch for a link (`theme_came_from_a_repo`, `omarchy-theme-set:204-208`) and `omarchy-theme-update` never pulls one, via `omarchy-theme-extras:12` (verified beside `stage_theme`) |
| `hyprconf.clock` shipped as `plugins/hyprconf-clock`, not made by `omarchy plugin clone` (nor copied at install time) | clone hardcodes `<username>.<id>` — a username in shipped config is PII — and a copy made once on the box was frozen at the release that made it (4.0.2's hardening of its own `Panel.qml` never reached it); the shipped copy is versioned and synced every run like the other three, carries Omarchy's MIT `NOTICE`, loads the panel from the running Omarchy, and `test_plugins.py`'s parity test turns red on an Omarchy release that changes the clock |
| `~/.config/fastfetch/config.jsonc` symlink | Omarchy's layout is `/etc/fastfetch/config.jsonc`; the user directory is fastfetch's documented override and reads first |
| `/etc/firefox/policies/policies.json` | Firefox reads enterprise policies from root-owned paths only, and that path shadows the `distribution/` file Omarchy writes — so the file is Omarchy's policy `jq`-merged under `infra/firefox/policies.json` |
| Python in `lib/hyprconf/` | a bounded, tested module used in place via `PYTHONPATH` — never inline `python3 -c`, never copied into `~/.local/lib` |

## Live files — the symlink hazard

`hypr/bindings.lua`, `hypr/input.lua` and `hypr/looknfeel.lua` ARE the running config: `~/.config/hypr/*.lua` are symlinks into the checkout. Every save must parse (`luac -p hypr/*.lua`), state only deltas from `/usr/share/omarchy/default/hypr/`, and any command a new bind runs must already be on PATH — `command -v` it before you commit; `test_hypr_overrides.py` covers only the `hyprconf-*` half, and Hyprland runs a missing target as a silent no-op; never leave a half-edited file. `mainMod` is `SUPER`; one bind per line; every key Omarchy also binds is `hl.unbind`ed first — digits and `-`/`=` through `unbind_keycode()` as well; never restate a bind Omarchy already has (`SUPER+P`, arrows, scroll, mouse drag — `test_hypr_overrides.py`); a hotkey that launches a program outside Omarchy's base adds it to `packages`. A new preset: the seed list in `stage_monitors`, the usage line of `hyprconf-monitor-preset`, a README row, tests in `test_monitor_preset.py` / `test_omarchy_install.py`. A desk preset names its displays `output = "desc:<make> <model>"` — never a connector, which renumbers when a cable moves between GPUs — carries no serial (PII), and ends with the `output = ""` catch-all; `test_hypr_overrides.py` pins all three.

## Scripts

- `#!/usr/bin/env bash` and `set -euo pipefail`; a script that deviates (the hooks and `hyprconf-yubikey` drop `-e`, `hyprconf-stats` is `set -u`) says why in a comment.
- Runtime Hyprland changes go through `hyprctl eval` and `hyprctl dispatch 'hl.dsp.…'` (quirks). A hotkey-launched script with something to say says it through `omarchy-osd` / `omarchy-notification-send` (`hyprconf-monitor-preset`); `hyprconf-gaps` says nothing — the gap change is its feedback, and its one failure (`hyprctl eval` refusing) is stderr + exit 1, invisible from the hotkey and accepted. No `pkill` / `killall`.
- Anything outside `$HOME` a script reads or writes sits behind a `: "${_HYPRCONF_X:=/default}"` seam — the Omarchy tree through Omarchy's own `OMARCHY_PATH` (`default/bash/env-bootstrap`), the feeders through `HYPRCONF_STATS_*` / `HYPRCONF_GPU_*` — never `readonly` (lists: CONTRIBUTING › Writing hermetic tests). One read stays unseamed because a miss is a no-op: `is_lit`'s `/sys/class/drm` glob in `hyprconf-monitor-preset`.

## Branches, publish, deploy

- `dev` is the working branch; `stable` is what users clone and what `hyprconf.sh` serves. Only `scripts/publish` writes `stable` (the three gates → tag `v$(<VERSION)` → one atomic push of `dev`, `stable` and the tag), and only when the user says "publish", with CI green on `dev`. Never push to `stable` by hand; never push anywhere unless the user asks; commit when asked.
- Nothing in the repo deploys. The website upload is by hand, only when the user says "deploy", after a publish, and always `stable`'s `install.sh`: CONTRIBUTING › Updating the website.

## Commits and versions

- [Conventional Commits](https://www.conventionalcommits.org/): `<tag>(<scope>): <message>`, subject ≤ 140 characters; tags `feat fix docs style refactor perf test build ci chore revert`; `!` or a `BREAKING CHANGE:` footer for removed or renamed hotkeys, stages, flags, plugin ids or paths. Name the Omarchy version the change was verified against.
- [SemVer](https://semver.org/) in the top-level `VERSION` file, bumped by hand in the commit that earns it — minor for a `feat`, major for a breaking change. `scripts/publish` reads it and takes no options; it refuses a tag that already exists on another commit.

## Tests

- Two hermetic suites, `tests/unit` and `tests/integration`, and that is the whole suite; behaviour that needs a live session is verified by hand and recorded in the commit message. Tree and seam lists: CONTRIBUTING › Testing.
- Hermetic: both pass in a bare `archlinux:latest` container as an unprivileged user — no Hyprland or shell, no hardware, no real `$HOME`, no ambient state (identity, groups, a TTY are injected — `_HYPRCONF_ASSUME_TTY`), never mutating the container. `$HOME` is relocated wholesale; everything outside it is behind `OMARCHY_PATH` or a `_HYPRCONF_*` / `HYPRCONF_STATS_*` / `HYPRCONF_GPU_*` seam.
- Every command that could touch the desktop or the system is a fake bin first on PATH — `/usr/bin` carries every `omarchy-*` command, so every one a code path can call is stubbed. Pure tools (`jq`, `luac`, `qmllint`, `shellcheck`, `sh`, coreutils — the list: CONTRIBUTING › Writing hermetic tests) are real when present and the test skips otherwise; `git` is required (throwaway trees under `tmp_path` only); `omarchy-plugin-validate` is the one real `omarchy-*` command a test runs.
- Harness: the repo-root `conftest.py` hands every test the `box` fixture — a throwaway machine (tmp `$HOME`, `/etc` and `$OMARCHY_PATH`, and a fakes dir first on PATH holding a recording stub for every `omarchy-*` name the tree carries, derived from it) with `box.stub()`, `box.run()` / `box.core()` / `box.undo()`, `box.calls` / `commands` / `calls_of()` and `box.reset()`. A new test uses it; `tests/unit/test_omarchy_install.py` still carries `install.sh`'s own older harness (`_setup`, `_stub`, `_run`, `_calls`, `PAYLOAD`, `_checkout`), which the module migration retires stage by stage.
- CI has **no git identity** — the container has no `~/.gitconfig`, and a bare `git commit` there dies "unable to auto-detect email address": the root `conftest.py` exports `GIT_AUTHOR_*` / `GIT_COMMITTER_*` for the session, and every git a test runs inherits them.

## Gates and CI

Before every commit: `make check` — `make lint` (ruff check + format), `make shellcheck` (find-based; fails when it finds nothing) and `make test` (`pytest -n auto -rs`), the three gates `scripts/publish` runs; `make` alone runs only the suites. `.github/workflows/test.yml` runs the same `make check` on every push to any branch, in `archlinux:latest`, as an unprivileged `ci` user the job creates and gives the checkout to — root would bypass DAC, trip `install.sh`'s refuse-root preflight and make git call the workspace dubious. Exactly two tests skip there — `test_installed_plugins_pass_omarchy_plugin_validate` and `test_clock_plugin_tracks_omarchys_stock_clock`, which need the installed Omarchy; any other skip is a regression, and `-rs` names every skip in the log. CI must be green before a publish, and CI on the push is the container gate — the pre-push check is `make check`. Read a red run from its `::error::` **annotation** — the one part of a red run the public API hands back; the why is in the comment beside the tee step in `.github/workflows/test.yml`, and that step stays when the workflow is edited. Reproduce a container-only failure — the no-Omarchy `/usr/bin` where an unstubbed `omarchy-*` call fails loudly, the bare freshly-upgraded toolchain — with:

```bash
docker run --rm -v "$PWD":/src:ro archlinux:latest bash -c \
  'pacman -Syu --noconfirm --needed git make ruff python python-pytest python-pytest-xdist jq shellcheck diffutils lua qt6-declarative &&
   cp -r /src /repo && useradd -m ci && chown -R ci: /repo && cd /repo && su ci -s /bin/bash -c "make check"'
```

## Known quirks (Omarchy 4.0.3-1, Hyprland 0.56.2, Firefox 155.0.1-1, Bash 5.3 — re-verify on upgrade)

- `hyprctl keyword` is a no-op — prints "keyword can't work with non-legacy parsers. Use eval." and exits 0 — and `dispatch dpms on` errors under the Lua parser: use `hyprctl eval` (exit 7 on error) and `hyprctl dispatch 'hl.dsp.…({ … })'` (forms in `hypr/README.md` › Runtime).
- Omarchy binds digits and `-`/`=` by keycode (`SUPER + SHIFT + code:20`, `default/hypr/bindings/tiling.lua`), which `hl.unbind` of the keysym does not match — both fire; `unbind_keycode()` in `bindings.lua` is load-bearing.
- `omarchy refresh config hypr/<file>` / `omarchy refresh hyprland` `cp -f` through the override symlinks into the checkout (`omarchy-refresh-config`): `restore_clobbered_override` and its stock cache under `~/.local/state/hyprconf/stock/` are the guard. Keep the links, the guard and the cache — the why is written beside it in `install.sh`.
- `omarchy-update` re-execs under `script(1)` with `OMARCHY_UPDATE_LOGGED=1`, so every hook child has a pty and `[[ -t 1 ]]` is true there: anything the overlay prints or asks on that path gates on that variable, never on the tty test. Nothing does today — the overlay asks nothing at install time.
- A prompt runs only on a TTY: every one has a non-interactive path (`--yes`, or a refusal that says so) and `_HYPRCONF_ASSUME_TTY` for the suite. `hyprconf-yubikey` is the only tool that asks.
- Bar widgets never size off `parent`: the ModuleSlot takes its height from the widget's implicit size, so `parent.height` is a binding loop QML drops — bind `implicitWidth` / `implicitHeight` to content.
- `omarchy plugin clone` hardcodes `${USER}.<id>`; the registry swaps a `clonedFrom` copy into the stock slot at enable time only, and `shell.json`'s `bar.centerAnchor` does no clone resolution — `follow_center_anchor` moves it after the clock swap — and on every run, since an anchor can go stale long after the install (a removed clone leaves one naming nothing); its guard, not the clock marker, is what keeps a user's own anchor safe.
- A long-lived shell can refuse a *newly added* `entryPoints.service` with Qt's `File name case mismatch` (`WARN qml: service plugin load failed for <id>`) while the widget draws its null-service defaults. Nothing on disk is wrong — it is shell-lifetime state, not a plugin defect: `omarchy restart shell` clears it, so restart before changing the plugin.
- Firefox: the `Preferences` policy's silent allowlist drop (a `startsWith` prefix match, and the `"Type"` rule every int-valued pref carries), the `browser.uiCustomization.state` seeding rules, the built-in themes' `inApp` quirk that leaves `:root[lwtheme]` off and `SearchEngines` applying on release are pinned — with their sources, the version each was verified on and the recipe to re-derive them — in `tests/unit/test_firefox.py`, `tests/unit/test_firefox_theme.py` and `lib/hyprconf/firefox_theme.py`. Read those before touching `infra/firefox/` or `themed/`.
- Bash 5.3: `$(< file 2>/dev/null)` returns empty — use `read -r var < file` or `$(cat file 2>/dev/null)`.
- Never `git update-index --skip-worktree` — it hides tracked files from the working tree.
- Branding: `.hyprconf` (leading dot), except the domain `hyprconf.sh`, binaries `hyprconf-*` and plugin ids `hyprconf.*`.

## How to work here

1. Read this file; read the README section and the code comments for what you touch — they carry the reasoning.
2. Verify every Omarchy fact on the box before changing anything (rule 2).
3. Change code, tests and docs together; keep `README.md`, `docs/CONTRIBUTING.md` and this file in lockstep, one home per fact.
4. `hypr/*.lua` are live — every save luac-clean, deltas only, targets on PATH.
5. Run `make check` before every push; CI on the push is the container gate.
6. Commit when asked. Never push, publish or deploy unless the user says so, in those words. `.claude/settings.json` holds the deny/ask rules that back this line and rules 2–3 — a speed bump the model cannot talk itself past, not a boundary: they match command text, and do not reach a script that opens files itself.
